# X86 Stock v1.6 — Safety-First Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Ship a safer, more convenient Android X86 Stock v1.6 without changing server transactions, prices, payments, stock quantities, or the existing scanner/PDF flow unless compatibility has been verified.

**Architecture:** Evolve the existing Java WebView shell in small pull requests. Extract tiny testable policies from \`MainActivity.java\`, gate UI enhancements behind locally controlled flags, keep original behavior available, and require device regression testing before the signed APK is released. The stock server remains the source of truth.

**Tech Stack:** Java / Android (minSdk 26, targetSdk 35), Gradle 8.9 / JDK 17, AndroidX SwipeRefreshLayout 1.1.0, JUnit 4.13.2 (added), Android instrumented tests where supported, GitHub Actions.

**Spec:** \`docs/superpowers/specs/2026-10-23-x86-stock-ux-modernization-design.md\`

## Global Constraints

- Keep \`applicationId = kz.x86.stock\`, \`minSdk = 26\`, \`targetSdk = 35\`; current released baseline is \`versionCode=5\`, \`versionName=1.5.0\`; v1.6 becomes \`versionCode=6\`, \`versionName=1.6.0\` **only at final release gate**.
- Starting URL stays \`https://x86.kz/stock/\`, with the existing PHP X86 Stock server as the authoritative source.
- Retain the current release key alias \`x86-release\` and the EXISTING signing certificate. Never commit a keystore, API token, password, signed transaction, or customer data.
- Current signing secrets are \`X86_KEYSTORE_BASE64\` and \`X86_KEYSTORE_PASSWORD\`. Signing verification must not disclose secrets.
- Preserve current login/cookies; search; stock; cashier permissions; scanning; sales and returns; receiving/purchases; prices; all payment types (cash, Gold, Red, installments); PDF, file upload/download; and Back behavior.
- Do not auto-retry a sale, refund, payment, or stock write after an unknown result. No new financial arithmetic in Android.
- Do not modify the production PHP site/DB from this repository. Search, cashier-mode, and server-integrated UI upgrades beyond v1.6 require separate server source/staging access and plans.
- Work on feature branches and PRs. Do not change \`main\` directly. Any rollback is via an OFF switch or a higher \`versionCode\`, **not** silent APK downgrade.

## Review Focus

1. Foreign \`https://*\` or iframe requests camera/bridge access: deny and keep trust boundary even after login redirects; test origin exactness and iframe calls.
2. Uncertain server write during connection failure: show “Статус операции неизвестен”; do not automatically repeat the sale/return; test simulated timeout/disconnect.
3. Pull-to-refresh while text is edited, checkout open, file picker/scanner active, or state unreadable: do nothing; preserve inputs.
4. Rotation, app background/foreground, keyboard display, and Android Back with an open product modal: preserve or safely close UI, never clear checkout silently.
5. APK on device signed by old key vs newly produced APK: version and signing certificate must match expectations before allowing release; compare *both* packages.

## Deferred, separate plans

- **v1.7 Scanner:** native or hybrid scanning + flash/vibration/audio, bulk scanning, role-respecting actions, explicit confirmation, legacy fallback.
- **v1.8 Search/navigation:** rapid P/N/barcode/model search, long-press item actions, gesture controls, customizable bottom menu, reliable saved filters; requires server-source review.
- **v1.9 Documents/updates:** simultaneous PDFs, label printing 50×30 with real printer validation, notifications reflecting confirmed server results, signed in-app APK update UX.

## Self-review and hold points

- Task 1 is a hard prereq for release: keep hash of attached APK and separately verify GitHub-signed artifact; installation compatibility is proven by the signer and package, not just by APK build success.
- Security work **does not** presume the existing \`addJavascriptInterface\` bridge is iframe-safe. Document its residual risk until verified migration is complete.
- Web-owned search/cart/form state is not silently migrated or overwritten by Android wrappers.
- Underlying monetary operations are out-of-scope for Android; any server change needs another spec.
- This document is **an implementation plan, not an implementation report**. The existing working v1.5 remains unchanged in this documentation branch.

**Execution recommendation:** native sequential implementation, starting with Phase 0 as an independent reviewed PR, then each remaining task on its own PR; limited rollout only after actual device QA.
